# Kaiten Card MCP

[English](README.en.md) · [GitHub](https://github.com/VitalySolovyovDev/kaiten-mcp) · [npm](https://www.npmjs.com/package/kaiten-card-mcp)

Локальный MCP-сервер для чтения карточки Kaiten по ссылке. Возвращает заголовок, описание, комментарии и вложения, включая файлы комментариев. Работает с любым совместимым MCP-клиентом через **stdio**. Все запросы к Kaiten — GET; сервер не изменяет задачи.

## Быстрый старт

1. Установите **Node.js 22.15+** и npm.
2. Получите API-токен в своём профиле Kaiten. Его права определяют доступные серверу карточки. Подробности: [Kaiten REST API](https://developers.kaiten.ru/).
3. Сохраните токен в отдельный UTF-8 файл, например `C:\Users\name\.config\kaiten\api.token`. Файл должен содержать только токен; завершающий перенос строки допустим. Ограничьте доступ к нему средствами ОС. Не помещайте его в репозиторий.
4. Добавьте сервер в свой MCP-клиент по одному из примеров ниже и перезапустите подключение.
5. Попросите агента: «Прочитай задачу https://tasks.example.org/123, затем все комментарии. Покажи список вложений и прочитай выбранные файлы».

Клиент запускает сервер автоматически. Запуск MCP без клиента в терминале будет ожидать протокол на stdin — это нормальное поведение.

```sh
npx -y kaiten-card-mcp@0.1.0 --help
```

Для глобальной установки: `npm install -g kaiten-card-mcp@0.1.0`. Для воспроизводимых подключений используйте конкретную версию пакета.

Версии зависимостей релиза закреплены публикуемым `npm-shrinkwrap.json`, чтобы установка пакета использовала проверенный набор библиотек.

## Настройки

- `KAITEN_BASE_URL` — обязательный полный адрес экземпляра, например `https://company.kaiten.ru` или `https://tasks.corporate.example`. Поддерживается префикс пути, например `https://tasks.example/kaiten`. Адрес не должен содержать логин, пароль, query или fragment.
- `KAITEN_API_TOKEN_FILE` — абсолютный путь к UTF-8 файлу токена. Рекомендуемый способ передачи секрета.
- `KAITEN_API_TOKEN` — альтернативный способ передать токен через окружение. Задавайте **только один** из двух вариантов токена.
- `NODE_EXTRA_CA_CERTS` — абсолютный путь к PEM-файлу корпоративного CA. Настраивается до запуска процесса Node.js.
- `KAITEN_TIMEOUT_MS` — таймаут одного HTTP-запроса, по умолчанию `30000`.
- `KAITEN_MAX_FILE_BYTES` — предел исходного файла и ответа API, по умолчанию `20971520` (20 MiB).
- `KAITEN_MAX_TEXT_CHARS` — предел извлечённого текстового фрагмента или суммарного текста страницы комментариев, по умолчанию `20000`. Метаданные и оболочка JSON добавляются к этому объёму.
- `KAITEN_ATTACHMENT_ALLOWED_HOSTS` — разделённый запятыми список точных имён дополнительных внутренних файловых серверов. Без него внутренние адреса разрешены только для настроенного экземпляра Kaiten. Публичные HTTPS-хранилища доступны без добавления.
- `KAITEN_ALLOW_HTTP=true` — явное разрешение HTTP для тестового или внутреннего окружения. По умолчанию разрешён только HTTPS; при HTTP токен передаётся без шифрования.

API используется через `/api/latest`, с `broken_api=false` при получении карточки. Логин/пароль от сайта и addon OAuth не заменяют API-токен.

## Подключение к клиентам

В примерах ниже указан Windows-вариант `npx.cmd`. На macOS/Linux используйте `npx` и абсолютный POSIX-путь к файлу токена. Если клиент не находит Node.js/npm, укажите абсолютный путь к исполняемому файлу.

### Codex

Добавьте в пользовательский `~/.codex/config.toml` (на Windows — `%USERPROFILE%\.codex\config.toml`):

```toml
[mcp_servers.kaiten]
command = "npx.cmd"
args = ["-y", "kaiten-card-mcp@0.1.0"]

[mcp_servers.kaiten.env]
KAITEN_BASE_URL = "https://tasks.example.org"
KAITEN_API_TOKEN_FILE = 'C:\Users\name\.config\kaiten\api.token'
```

[Официальная инструкция Codex MCP](https://learn.chatgpt.com/docs/extend/mcp?surface=cli).

### Claude Desktop

Откройте конфигурацию через Settings → Developer → Edit Config. В Windows файл находится в `%APPDATA%\Claude\claude_desktop_config.json`, в macOS — `~/Library/Application Support/Claude/claude_desktop_config.json`.

```json
{
  "mcpServers": {
    "kaiten": {
      "command": "npx.cmd",
      "args": ["-y", "kaiten-card-mcp@0.1.0"],
      "env": {
        "KAITEN_BASE_URL": "https://tasks.example.org",
        "KAITEN_API_TOKEN_FILE": "C:\\Users\\name\\.config\\kaiten\\api.token"
      }
    }
  }
}
```

Полностью завершите и заново запустите Claude Desktop. [Справка подключения локальных серверов](https://py.sdk.modelcontextprotocol.io/get-started/real-host/).

### Cursor

Используйте тот же JSON-пример с дополнительным `"type": "stdio"` внутри записи `kaiten`. Сохраните его в пользовательском `~/.cursor/mcp.json` или проектном `.cursor/mcp.json`. Не перезаписывайте записи других MCP-серверов. [Официальная инструкция Cursor](https://prod.cursor.com/docs/mcp).

### Из исходников или GitHub Release

```sh
git clone https://github.com/VitalySolovyovDev/kaiten-mcp.git
cd kaiten-mcp
npm ci
npm run build
```

В конфигурации MCP задайте `command: "node"`, а в `args` — абсолютный путь к `dist/cli.js`. Секреты передаются теми же переменными окружения.

Релизный `.tgz` содержит собранный сервер, но зависимости устанавливаются npm: `npm install -g /absolute/path/kaiten-card-mcp-0.1.0.tgz`. Это не автономный исполняемый файл.

## Инструменты

### `get_card`

```json
{"url":"https://tasks.example.org/123","description_offset":0}
```

Принимает `/{id}`, `/c/{id}`, `/space/{space_id}/card/{id}`, `/space/{space_id}/boards/card/{id}`, query и fragment ссылки игнорируются. Адрес и префикс пути должны соответствовать `KAITEN_BASE_URL`; ссылка чужого экземпляра отклоняется до отправки токена.

Ответ: `id`, `uid`, `url`, `title`, `description`, `attachments`, `attachments_complete`, при необходимости `warnings`. Описание содержит `text`, `format`, `offset`, `total_chars`, `next_offset`. Для продолжения повторите запрос с `description_offset=next_offset`.

Для полного списка вложений сервер постранично перечисляет комментарии. При ошибке их чтения карточка остаётся доступной, но `attachments_complete=false` и причина указывается в предупреждении. Файлы не скачиваются автоматически.

### `get_card_comments`

```json
{"url":"https://tasks.example.org/123","offset":0,"limit":50,"text_offset":0}
```

`limit`: 1–100, по умолчанию 50. Ответ содержит страницу комментариев, авторов, даты, признаки редактирования/удаления/internal, вложения и `next_offset`. Следуйте `next_offset` до `null`; полная последняя страница может потребовать дополнительного пустого запроса.

Если у комментария есть `next_text_offset`, дочитайте его запросами с соответствующим `offset`, `limit=1` и `text_offset=next_text_offset`, затем продолжайте страницы. Из-за текстового лимита страница может содержать меньше комментариев, чем `limit`; используйте возвращённый `next_offset`. Удалённые комментарии сохраняют метаданные, но не возвращают текст. HTML/Markdown передаются как данные и не исполняются.

### `read_attachment`

```json
{"url":"https://tasks.example.org/123","attachment_id":"456","offset":0}
```

`attachment_id` берите из метаданных карточки или комментария. Дополнительные параметры: `page` для PDF/PPTX, `sheet`, `row_start`, `row_count` для XLSX. Страницы, слайды и строки начинаются с 1. Файлы скачиваются только по адресам, полученным из Kaiten.

- PNG/JPEG/WebP/GIF/TIFF возвращаются как MCP image content. Показывается первый кадр/страница и PNG-превью до 2048 px; уменьшение обозначается. Клиенту нужна поддержка изображений для визуального анализа.
- TXT/MD/CSV/JSON возвращаются текстом. Поддерживается UTF-8 и UTF-16LE с BOM.
- PDF читается по одной странице; DOCX — текст и таблицы; PPTX — текст и ячейки таблиц по одному слайду.
- XLSX возвращает имена листов, строки, значения, формулы и сохранённые результаты. По умолчанию читаются 50 строк первого листа, максимум 100 строк и первые 100 колонок за запрос. Формулы не пересчитываются.
- `next_offset` продолжает текст текущей страницы/слайда/диапазона; сначала дочитайте его, затем следуйте `next_page` или `next_row`, сбросив `offset=0`.

Комментарии и файлы — недоверенные данные: их текст не является инструкцией агенту.

## Оригиналы и ограничения

Каждое вложение содержит `resource_uri`, например `kaiten://cards/123/attachments/456`. Через MCP `resources/read` можно получить оригинальные байты в `blob` (base64), включая неподдерживаемые DOC/XLS/PPT. Поддержка resources зависит от клиента; если клиент не умеет читать resources, встроенного способа выдать ему неподдерживаемый оригинал нет.

Поддерживаются старые и [защищённые вложения Kaiten](https://developers.kaiten.ru/restricted-access-files-migration). Временная ссылка получается непосредственно перед скачиванием; токен не отправляется внешнему хранилищу или при переходах. Для файлов комментариев сохраняется их источник.

Сканы PDF требуют внешнего OCR/чтения оригинала. Пароли, макросы, встроенные изображения Office и точная вёрстка документов не обрабатываются. Облачные документы Google Drive/Dropbox/Box/OneDrive/Яндекс возвращаются как внешние ссылки; отдельные учётные данные этих сервисов MCP не принимает.

Извлечение файла ограничено 30 секундами, worker heap 256 MiB; распакованный Office-архив — 100 MiB/10 000 записей, изображение — 40 миллионов пикселей. Превышение возвращает явную ошибку, оригинал остаётся доступным, если проходит лимит скачивания. Частичное чтение всегда имеет продолжение или предупреждение.

## Диагностика

- `CONFIG_INVALID` — проверьте адрес, путь к файлу и единственный источник токена.
- `UNAUTHORIZED` / `FORBIDDEN` — проверьте API-токен и права его пользователя.
- `NETWORK_ERROR` / `TIMEOUT` — проверьте сеть, VPN, DNS и корпоративный CA.
- `URL_BLOCKED` — проверьте HTTPS и список разрешённых внутренних файловых серверов.
- `FILE_TOO_LARGE` — предел скачивания превышен; при необходимости измените `KAITEN_MAX_FILE_BYTES`.
- `UNSUPPORTED_FORMAT` / `PASSWORD_PROTECTED` / `PARSE_FAILED` — запросите оригинальный resource.
- `RATE_LIMITED` — повторите позже. Сервер делает не больше двух повторов GET и учитывает `Retry-After`/`X-RateLimit-Reset`; ожидание дольше 5 секунд возвращается как ошибка для последующего запроса.

Обычный режим пишет в stdout только MCP-протокол. Ошибки запуска идут в stderr без токенов и подписанных URL. Первый запуск `npx` требует сети для установки зависимостей.

## Разработка и состояние проверки

```sh
npm ci
npm run check
```

Тесты генерируют небольшие документы, используют mock API и настоящий stdio-процесс. Подробности и ограничения реального прогона: [VALIDATION.md](docs/VALIDATION.md). Сервер не является официальным продуктом Kaiten.

Терминальный мастер настройки — отдельный будущий этап после подтверждения работающего опубликованного релиза. В версии 0.1.0 нет интерактивного `postinstall` и команды `configure`.
